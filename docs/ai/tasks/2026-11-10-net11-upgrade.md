## Request and decisions

Upgrade all .NET projects to installed .NET11, preserve behavior, measure against
.NET10 and publish. Existing projects now target net11.0; SDK 11.0.100/latestPatch
is pinned. ASP.NET Core/EF/SignalR/Extensions packages use11.0.0. Windows OS
platform suffixes are retained in the related projects.

Removed Pkcs and DI.Abstractions direct references now supplied by the framework,
following SDK NU1510 diagnostics. Updated both folder publish profiles. Business
operations, generated JSON, streaming, cancellation, authorization and data remain.

Identical benchmark source/fixtures are compiled Release/x64 under SDK10/runtime
10.0.9 and SDK11/runtime 11.0.0. The API harness uses actual NDJSON and OutputCache
paths; the serial runner alternates process order. Only numerical results are
published. Shared policy revision2026-11-10.2 selects .NET11 for current work.

## Measured comparison

The coordinated .NET10/.NET11 run completed with five alternating process runs
per version. The numerical report includes 69 cases across EF, real read-only SQL
operations, API/OutputCache, SDK and Windows headless paths. All 530 SQL result
hash/query-count comparisons matched. These are selected component benchmarks,
not a claim about complete application RAM or rendered UI performance.

[Full report and methodology](https://github.com/Shahesmaeili/Mizon.Server.API/blob/main/docs/performance/net11/README.md)

Final combined validation: all36projects built, including main WinUI Debug/Release.
Database and SDK actual NativeAOT suites passed; Windows MCP/navigation/pinning
NativeAOT and existing scoped permission/lifecycle checks passed. See the report's
verification matrix for counts and the explicit full-application AOT limitations.
